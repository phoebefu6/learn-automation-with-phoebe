Learn Automation with Phoebe

Automate the boring parts with Zapier, Make or n8n, and build them so they do not break. Most automation tutorials end when the first run turns green. The trouble starts later: a reply that never arrives after the message already went out, a provider that is down for half an hour, a retry that texts a customer twice, a run that fails silently and an order nobody hears about. Six sessions on deciding what is worth automating, how a trigger hands data to an action, what each tool really charges for, and the four rungs between a workflow that works on Tuesday and one you can leave running for a year.

The six sessions 🎯 · from "this is boring" to a workflow with an owner

The running example is one workflow: an order arrives by webhook, the customer is looked up, and a text message goes out. You import it into n8n on your own machine in session 2, run four versions of it on the bench in session 4, and give it a runbook in session 6. Every build-along runs without a paid account.

⏳ Session 1 · foundations

Is it worth the time?

Frequency x minutes x lifetime against build plus upkeep. xkcd 1205 read cell by cell, the two costs it leaves out, and the Google SRE argument that time is not the only return. Price five of your own tasks.

▶ Start here 🔌 Session 2 · core

Triggers, actions and the data between

Instant versus polling triggers, what an item, a bundle and a field are, and how one step reads another's output. Run n8n locally, import a real five-node workflow, and follow one order through it.

n8n on your machine 🧮 Session 3 · core

Zapier, Make or n8n

Tasks, credits and executions: what each tool bills, read from its own pricing pages and dated. Self-hosting versus cloud, what n8n's licence allows, and the same workflow priced three ways.

dated pricing, re-verify 🎛️ Session 4 · bench night

The workflow bench

Real n8n-format workflows over a seeded day of 600 events with timeouts, 500s, lost replies and an outage. No retry, retry everything, an idempotency key, a dead-letter queue, and a button that breaks the fix.

★ the bench 🧯 Session 5 · applied

When a step fails

Retries with backoff and jitter, idempotency keys and what to do when the app has none, a dead-letter list you will actually read, and an alert that names the order. Built in n8n, mapped to Zapier and Make.

build the rungs 🗂️ Session 6 · applied

Leave it running

An owner, a runbook, an inventory and a review date for every automation. The state that silently resets, the key windows that expire, and how to retire an automation before it retires you.
