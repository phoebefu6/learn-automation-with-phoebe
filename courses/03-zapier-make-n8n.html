Learn Automation with Phoebe · Session 3 of 6

Zapier, Make or n8n

The three tools look alike on a demo: boxes, arrows, a green tick. They stop looking alike on the invoice, because each one counts a different thing. Zapier counts successful actions, Make counts every module that runs, and n8n counts whole runs. Put the same five-step workflow on all three and you get 2, 4 and 1 units for one order. Tonight we read what each meter ticks on, put the plan tables side by side with a date on every number, price the bench workflow at three volumes, and ask the question that decides more than price: who runs the server, and under what licence.

Part 0

Where we start

You arrive with one sentence from session 1 and one workflow from session 2: when an order comes in, look the customer up and text them. Before you build it for real, you have to pick where it lives. The usual way to choose is to compare monthly prices, and that comparison is nearly meaningless until you know what one unit of each price buys. A task, a credit and an execution are not three names for the same thing. Count your workflow in each unit first, then read the price.

Part 1 · covers what each tool bills

Three meters on one workflow

6 min live

Take the bench workflow: a webhook receives an order, an IF lets only orders through, a Set step shapes the message, one HTTP call looks up the customer and a second sends the SMS. Run it once on each tool and watch where the meter ticks. Zapier ticks on the two calls that reach another server, and only if they succeed. Make ticks on every module that runs, trigger included. n8n ticks once for the whole run. Same order, same five steps, three different counts.

LiveThree units, one workflow3 min▶

Zapier bills a task. In Zapier's own words, "A task is any successful action that runs in Zapier. Only successful actions count." The trigger is free, and so are the built-in helper steps: Filter, Paths, Formatter, Delay, Looping, Digest and Storage. On the bench workflow that leaves the two HTTP calls, so a successful order costs 2 tasks. A signup that the Filter stops costs nothing beyond the free trigger.

Make bills a credit. Since 27 August, credits are Make's billing unit; before that the same thing was called an operation, defined as a single module run to process data or check for new data. For ordinary non-AI apps, one module run is one credit, and the trigger module counts too. Routers and error-handler modules are free, and a filter sits on the route between modules rather than being a module itself. On the bench workflow that is trigger, Set and two HTTP modules: 4 credits an order.

n8n bills an execution. n8n's docs: "An execution is a single run of your entire workflow. It doesn't matter how many steps are in the workflow or how much data it processes." Five nodes or fifty, the order costs 1 execution. Only production executions count; runs you start by hand in the editor while building do not.

So the honest first question is never "which is cheapest?" but "how many of each unit does my workflow burn per run?" The answer depends on the shape of your workflow: many steps per run favours a per-run meter, few steps on a per-step meter can still be cheap.

Self-studyThe fine print that changes the count4 min▶

Failed steps. On Zapier, "All action steps that error or halt" are free (Zapier Help, "How is task usage measured in Zapier", updated 2026-08-21). So a send that errors costs nothing, and the retry that succeeds costs one task. On Make, the pages read for this session do not say whether a module run that fails uses a credit. The bench in session 4 assumes it does and says so on the widget; treat that as an assumption, not a fact, until Make documents it.

Replays. Zapier's Autoreplay replays the errored step (Professional plans and above). A full replay of a run is different: it re-counts the steps that had already succeeded the first time. Replay the step, not the run, when you can. Zapier's page does not state the Autoreplay schedule; do not assume one.

AI modules. On Make, some AI modules use 2 or 10 credits per run instead of 1 (Make Help, "Credits"). One AI step can cost as much as ten plain steps. Check the module before you count it as 1.

Checks with nothing in them. Make counts a polling trigger check once even when it finds no new data. A trigger that checks every few minutes all day costs credits on a quiet day. A webhook trigger, which session 2 used, only runs when something arrives.

Manual runs. n8n does not count runs you start from the editor. That makes building and testing free on the meter, and it also means the number you see while building is not the number you will see in production.

Real world

The replay that charged twice. Zapier documents that a full replay re-counts every previously successful step. A common pattern: a five-action Zap fails on its last step, someone replays the whole run from the history page to be safe, and the four actions that had already worked run and bill again. Worse than the tasks, those four actions do their work again: a second CRM record, a second email. The meter and the side effect move together, which is the subject of session 5.

LiveReading a pricing page without being sold to3 min▶

Find the unit before the price. The big number on the card is a plan price. The small number under it, 750 tasks or 10,000 credits or 2,500 executions, is what decides your bill. Write both down together, always.

Find the toggle. Zapier shows two prices for the same plan: $29.99 billed monthly, $19.99 a month billed annually. Make and n8n show one figure and an annual saving ("Save 15% or more", "17%"). Until you have clicked the toggle yourself, you do not know which one you are looking at, which is why those two are "as displayed" here.

Find the overage rule. What happens at unit 751? On Zapier, pay-per-task overage when enabled is charged at 2.5x the base rate on monthly self-serve plans and 1.25x on annual. An automation that grows quietly past its plan is billed at the expensive end.

Find what is free. Free trigger, free filter, free error handler, free manual runs: these change your count more than a few dollars on the plan price. Part 1 lists them per tool.

Write the date. Make renamed its unit on 27 August. A screenshot from September and one from today may not describe the same product.

Self-studyWhy the per-unit number is a comparison device, not a quote3 min▶

Dividing the entry plan's price by its included units gives a tidy number: $0.0400 a task on Zapier ($29.99 / 750), $0.0009 a credit on Make ($9 / 10,000), €0.0080 an execution on n8n (€20 / 2,500). The bench in session 4 uses exactly these to put a money figure next to its unit counts, and labels it "mapped". It is useful for one thing: seeing how the same workflow scales on three meters.

It is wrong as a bill in four ways. Plans are bought in tiers, so a month that uses 760 tasks does not cost 760 x $0.0400. Overage is charged at a different rate. USD and EUR are not converted, and tax is left out. And the three units are different sizes of work: the bench's rung 1 day burns 621 tasks, 1,616 credits or 600 executions for the same 600 runs. The bench's rung 4 burns 714 Zapier tasks a day, about 21,000 a month, against a 750-task Professional plan; nobody pays 21,000 x $0.0400, because nobody would stay on that plan.

Use the device to compare shapes, then price the real tier on the real page.

What the calculator assumes. It counts runs x steps Zapier tasks, runs x (steps + 1) Make credits to include the trigger module, and runs n8n executions. On Zapier, enter only the action steps: Formatter, Filter and the trigger are free. On Make, every module counts, so if your scenario has a Set or tools module, it belongs in the steps too. For the bench workflow the honest inputs differ by tool: 3000 2 is right for Zapier (6,000 tasks · $239.92) and n8n (3,000 executions · €24.00), but its Make line (9,000 credits · $8.10) misses the Set module; 3000 3 gives the 12,000 credits the build-along script counts. The money is the per-unit device above, nothing more.

Real world

The unit changed name on a live pricing page. Make's pricing page FAQ now reads "As of August 27, credits are the billing unit in Make." Until then the same plans were sold in operations. For ordinary apps one operation equals one credit, so most counts did not move. AI modules are where they did: some now use 2 or 10 credits a run. Anyone comparing a saved spreadsheet of "operations" against today's page was comparing two different units without knowing it. Date every number you copy.

Part 3 · covers self-host versus cloud and the licence

Who runs the box

5 min live

Zapier and Make are cloud only: they run the servers, you rent the meter. n8n also sells a cloud plan, and on top of that its Community Edition is free to run on your own machine. Free to download is not the same as free to run, and not the same as open source. Two questions decide whether self-hosting is right: does the licence allow what you plan to do, and is there a person who will keep the box patched, backed up and up.

LiveWhat you take on when you self-host3 min▶

A server. Something has to be switched on all day for a webhook to land. A laptop that sleeps loses orders.

Updates. n8n ships often, and its runtime moves. The current stable on 5 October 2026, n8n 2.41.6, declares that it needs Node 24 or later, while n8n's own install docs still say Node 20.19 to 24.x. When the docs and the package disagree, the package wins at install time. Its startup log also warns: "Running n8n outside a container is deprecated." Plan on Docker.

Backups. Your workflows, credentials and execution history live in n8n's database on your box. If the disk dies, so do they, unless you copied them somewhere else on a schedule and once tried a restore.

Your own uptime. On cloud, an outage is the vendor's incident. Self-hosted, it is yours: at 13:00 on a Tuesday, the person who gets the message is you. Session 6 is about naming that person before the first outage, and the craft of a runbook for it belongs to the reliability course's runbooks session.

None of this is a reason not to self-host. It is the real price of "free", and it belongs in session 1's upkeep line.

Self-studyReading the Sustainable Use License4 min▶

n8n's Community Edition is published under the Sustainable Use License 1.0. Its central limit: you may use the software "only for your own internal business purposes or for non-commercial or personal use." Running it for your own company's orders, your household, or a hobby project is inside that. Selling n8n itself to other people as a hosted service is outside it, and that is the case where you talk to n8n about a commercial licence before building.

Not every file in the repository is under the same terms. Files with .ee. in their name are enterprise features and need an enterprise licence. If a feature you want lives in one of those files, the free edition does not grant it.

n8n calls this model "fair-code". The accurate plain description is source-available with limits: you can read the code and run it, under conditions. It is not open source in the OSI sense, which does not allow restrictions on field of use. Say "source-available" in a proposal and nobody can correct you; say "open source" and someone eventually will. And as with the prices, read the licence file itself, dated, rather than a summary of it, including this one.

Real world

The docs said Node 20, the package said Node 24. n8n's install page reads "n8n requires a Node.js version between 20.19 and 24.x, inclusive". On 5 October 2026 the stable npm package, n8n 2.41.6, declared node >=24.0.0, so on Node 22 the current release does not satisfy its own requirement. On Node 24 it started and answered its health check in about six seconds, and printed the container deprecation warning. Nothing was wrong with either page on the day it was written. That is the self-hosting job in miniature: two official sources disagree, and you are the one who has to notice.

Check yourself

Three questions

Clear all three and session 3 gets stamped in your passport.

1 · A Zap has one action, "send the SMS". On one run the action errors, and Autoreplay replays the errored step, which then succeeds. How many tasks did that action use?

Zapier: "A task is any successful action that runs in Zapier." Action steps that error or halt are free. Replaying the errored step bills the one success. Replaying the full run re-counts earlier successful steps, which is why you replay the step, not the run.

2 · On the session 4 bench, adding retries raises the Zapier task count and the Make credit count, but n8n's executions stay at 600 for 600 runs until the dead-letter redrives. Why?

"An execution is a single run of your entire workflow. It doesn't matter how many steps are in the workflow." A retry inside the run is still the same run. The count only rises when a new run starts, as with the 13 redrives on rung 4 (613 executions). And editor runs are the ones that do not count.

3 · What does n8n's Sustainable Use License allow you to do with the free Community Edition?

The licence limits use to "your own internal business purposes or for non-commercial or personal use". Reselling it as a service is outside that. n8n calls the model fair-code; describe it as source-available with limits, not as OSI open source.
